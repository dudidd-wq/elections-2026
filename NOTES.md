## Coalition builder (#/coalition, data/coalition.json)
- Data: tools/build_coalition.py codes each list per issue into the camps of analysis.json (scale: ordinal / degree+consensus / principle), with an evidence snippet asserted against the source text; uncoded cells get a reason. Declared refusals (shown separately, never in the score; same rule for every list): from the profile field "גוש / שותפויות מוצהרות" (DECL) and from explicit, unconditional campaign statements by the list leader with date + URL (DECL_SRC). Mapped only when naming a list, its leader, or "מפלגות ערביות" (joint+raam, site bloc) / "מפלגות חרדיות" (shas+utj) – GROUPS. Conditional or inference-needing statements are not mapped. Refusals counted as distinct (from,to) pairs. Not a complete record; the UI says so. (Audit 25.10: yb/miluim group statements had been half-mapped; Netanyahu refusals by yashar/beyachad/dems/yb added with sources. Joint housing uncoded as general-only.) Run automatically (non-fatal) by build_data.py and update_polls.py; rerun after any change to analysis/platforms.
- Distance per issue: same camp 0; ordinal steps/(k−1); degree 0.5 if both in the analysis consensus, else 1; principle 1; multi-camp lists = symmetric best-match average. Score = Σ w·(1−d)/Σ w ×100 over all pairs × issues; w = issue weight (0–3, default 1) × star weight of each list (* = 0.5 default; 1/0 options). Coverage = counted / possible pair-issue comparisons. Equal weight per list (not seat-weighted).
- Seats = sum of D.computed.average (tenths, 61 = 610). Minimal winning combos (≥61 and dropping any list falls below) from lists with avg ≥4 (th=all adds the rest). Range shown = score at * weight 0 and 1.
- Suggestions (round 2, 25.10, after "the suggestions don't make sense"): the mean hid extreme pairs (e.g. two lists opposed on most issues inside a high-mean combo). Now uniform per pair: pair index (coScore on the 2 lists), n = issues where both coded, full = issues at distance 1. A combo is shown only if EVERY pair has n ≥ 5 (CO_MINN) and rounded pair index ≥ mp (default 40; 25/50 selectable; no "off"). Order: weakest-pair index desc, mean desc, fewer full-gap issues, coverage desc, fewer lists, alphabetical. Declared refusals hide combos by default (nd=0 shows them); if none remain, the threshold-passing combos are listed with their refusal pairs named. Same filters in "מה צריך כדי להגיע ל-61" and by-list view. Card shows weakest pair + index, full-gap count, refusal pairs. No list-specific rule. Validation: /workspace/elections-2026-audit/coal/analyze.py new 40.
- Refusals added 25.10 round 2: Bennett→Otzma (ynet 20.2), Ben Gvir→Yashar+Beyachad (Ch14 10.9), Golan→gov37 group (= site "גוש נתניהו" lists).
- Hash: l=ids, w=10 digits, s=0|10, th=all, must=id, nd=0 (show combos with refusals), mp=25|50 (default 40), view=list, sort=gap, all=1.
- Rules: alphabetical defaults, no party-specific notes, no colors, no recommendation/forecast wording; "not a forecast" text in lead, suggestions and method. Tests: /workspace/elections-2026-audit/coal.mjs (+ noraamnotes routes).

## Exit polls (#/exit-polls) — how to add the 27.10.2026 exit polls
Page: `#/exit-polls` ("מדגמים: דיוק בעבר"). Data: `data/exitpolls.json`. 2019–2022 rows are built by `tools/build_exitpolls.py` (source of truth; every figure has a source URL + retrieval date; rebuild keeps `y2026` untouched). Test: `node test/exitpolls.test.mjs`.

2026 rows live only in `y2026` and are added with `tools/add_exitpoll_2026.py` (append-only; no delete/edit command exists — by design):
1. After 22:00 on 27.10.2026, for each channel's 22:00 poll (channel ids: `kan`, `c12`, `c13`, `c14`; list ids = `data/polls.json` parties, e.g. likud, yashar, beyachad, dems, joint, otzma, shas, yb, utj, rzz, raam, miluim, amcha):
   `python3 tools/add_exitpoll_2026.py add-poll --channel c12 --pollster "<pollster>" --time 22:00 --kind initial --seats likud=..,yashar=..,... --source <URL1> --source <URL2>`
   Seats must sum to 120; lists not given are 0 (below threshold in that poll). Record the numbers exactly as published, at least 2 sources if possible. Later updates: `--kind update --time 01:30`.
2. When the CEC publishes results: `python3 tools/add_exitpoll_2026.py set-results --label "ספירה חלקית (…% מהקלפיות)" --seats ... --source <CEC URL>`; call again for the final certified results (the previous one is kept in `resultsHistory`). Leave `--bloc` empty until the post-election recommendations to the President are public (same mechanical rule as 2019–2022), then call set-results again with `--bloc id1,id2,... --bloc-source <URL>`.
2b. Partial counts before the CEC publishes seats: `set-count --label "ספירה חלקית (…)" --as-of <ISO> --pct likud=20.68,... [--ballots N --valid N --turnout % --voters N --eligible N] --source <URL> --source <URL> --note "..."` (vote shares only, no seat metrics; previous count kept in `countHistory`). Extra 2026-only channels: `i24`, `c16` (stored in `y2026.channels`, never in meta.channels so 2019–2022 charts are unchanged).
3. After the final certified results: `python3 tools/add_exitpoll_2026.py freeze`. Frozen data is never changed or deleted.
4. Bump `VERSION` in sw.js, run `node test/exitpolls.test.mjs`, commit, push.
The page renders `y2026` automatically (table of polls; error metrics once results exist) with the same formulas as 2019–2022. No forecast text: the page never says who "will" win.

## Results by locality and ballot box (#/geo) — official CEC data, and how to add 2026
Page: `#/geo` (overview: turnout extremes, turnout change, per-list highest shares, all localities) and `#/geo/<locality code>` (turnout over time, list shares per election, list detail, paged/sortable ballot table). Code: `js/geo.js`, loaded only when the route opens (adds ~0 bytes to the first load). Data: `data/geo/index.json` (sources + sha256 + national totals + locality names), `data/geo/kNN.json` (one row per locality per election), `data/geo/loc/<code>.json` (one shard per locality: totals + every ballot box, all elections). The SW caches what was viewed (network-first), no geo precache.
- Source: data.gov.il dataset `votes-knesset` (publisher: ועדת הבחירות המרכזית), per-ballot and per-locality resources for K21–K25, pulled through the public `datastore_search` API (no key). votesNN.bechirot.gov.il and the direct CSV downloads returned 403 from the build box, so the sha256 in index.json is of the canonical JSON dump written by `tools/fetch_geo.py` (`{resource_id, retrieved, fields, records}`), not of the original CSV. Raw dumps stay outside the repo (`$GEO_RAW`, default /workspace/geo/raw).
- Build: `python3 tools/build_geo.py`. It asserts: voters = invalid + valid in every row; list votes sum to valid; the sum of ballots per locality equals the official per-locality file (all meta fields and every kept list); and kept letters = the short-name map. Lists ≥ 1% of national valid votes are kept; the rest are summed into "other".
- Envelopes (double envelopes: soldiers, diplomats, prisoners, hospitals, polling staff, special/accessible ballots) are the row `9999` (K21: `99999`, aliased) with eligible = 0. So locality turnout excludes them; the page shows both the national figure and the localities-only figure.
- Known data discrepancy: K22 eligible in the data.gov.il file = 6,391,218, published CEC figure 6,394,030 (turnout 69.86% vs 69.83%). Voters/invalid/valid and all list votes match the published results.
- Ballot numbers: K22+ include decimal sub-ballots (3.1, 3.2). Ballot numbers and voter assignment change between elections — the UI never links ballots across elections. Localities are matched by CBS locality code; 13 codes are absent from some elections (new/merged localities).
- No sector (Arab/Jewish etc.) aggregates: no documented official classification was used.
- Tests: `node test/geo.test.mjs` (sources/hashes, ballots→locality→national sums, official national totals). Live re-derivation from the API: `python3 tools/verify_geo_live.py 10` (10 random localities, seed 2026) or `python3 tools/verify_geo_live.py 5000,3000` (explicit codes). On 27.10.2026: 15 localities × 5 elections × 2 resources = 150 comparisons, 0 differences. UI smoke: /workspace/elections-2026-audit/geosmoke.mjs (axe + 320/360/390/desktop, light/dark).
- **Adding 2026 (K26)** — only after the CEC publishes the final per-ballot results on data.gov.il (not from live counts):
  1. `python3 tools/fetch_geo.py 26 <ballot-resource-id> <city-resource-id>`
  2. Look at the letters of lists ≥ 1% and create `data/geo/extra_elections.json`: `[[26, "2026", "2026-10-27", "אוקטובר 2026", "<ballot-id>", "<city-id>", {"מחל": "הליכוד", ...}]]` (short names = official list names from the CEC candidate lists; the build fails if the map does not match the lists ≥ 1%). Or add the same tuple to `ELECTIONS` in tools/build_geo.py.
  3. `python3 tools/build_geo.py && node test/geo.test.mjs` (add the official K26 national totals to `OFFICIAL` in the test once certified), check the envelopes code still is 9999 (else add to `CODE_ALIAS`), bump `VERSION` in sw.js and `GEO_V` in js/app.js, commit, push.
  The page picks up every election in index.json automatically (election chooser, time series, change vs previous). The note about 2026 on the page disappears once K26 is in the index.
